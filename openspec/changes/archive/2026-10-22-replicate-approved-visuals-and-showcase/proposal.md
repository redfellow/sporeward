# Proposal

## Why

The accepted browser guide is ahead of Android's state-specific visuals. A compact, deterministic showcase will let the owner inspect every state and its transitions without another outdoor outing or a large field-world load.

## What Changes

- Port the approved guide at commit `754a5c1` through shared rendering definitions to Android's native MapLibre path.
- Provide an isolated fixed showcase around Hatanpää, Viinikanlahti, Viinikka and Nekala, with every lifecycle, effort and personal-marker appearance.
- Add tester controls for scenario selection, fit/jump, reset and a paused/advanceable lifecycle clock while membrane motion continues.
- Exercise the same renderer and state transitions with recorded outings in the living replay world, then obtain emulator and phone approval.
- Add progressive zoom presentation: detailed artwork, simplified colour/state badges, small badges and tappable area summaries with a single centered combined count. Use an antenna badge for distant Field Labs.
- Double newly created remnant collection radii for route/GPS alignment tolerance, preserving shoreline/separation constraints and historical contact intervals.
- Preserve existing field accounts, recordings, scoring and historical matching.

## Capabilities

### New Capabilities

- `outbreak-visuals`: Consistent effort, lifecycle and personal-marker appearance across the web guide and Android map.
- `visual-showcase`: Isolated, repeatable geographic state fixtures and tester controls using normal gameplay rendering.

### Modified Capabilities

None. This is the first OpenSpec change; existing implementation is documented in `docs/`, not yet comprehensively baselined as OpenSpec specs.

## Impact

Shared `packages/rendering`, web `PaletteStudy`, mobile `RouteMap`, `RicherMapImages` and setup controls, plus isolated replay fixtures/API/tooling. Protocol additions may be needed for public crack presentation or scenario clock controls. Detailed gameplay balancing and size/category engine changes remain separate from this visual port; use `docs/game-concept.md` and preserve current mechanics rather than silently changing them. No field-world migration or deployment is authorized by this plan alone.
